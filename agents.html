项目规则

开发过程中必须遵守的规范

命名规范

  • 所有 CSS 类名必须以 tang_ 开头
  • 所有 ID 名必须以 tang_ 开头
  • 所有 JS 变量必须以 tang_ 开头

提示词记录

  • 所有提示词在执行之前必须写入文件 tang_prompt.md
  • 以追加方式写入，不覆盖之前的内容
  • 写入内容包括：
    • 时间（格式：yyyy-mm-dd-hh-mm）
    • 使用的模型
    • 提示词内容

代码风格

  • 使用 4 个空格缩进，不使用 Tab
  • CSS 属性按功能分组：定位 → 盒模型 → 文字 → 视觉 → 其他
  • CSS 属性按字母顺序排列
  • 使用单引号包裹字符串
  • 语句结尾必须添加分号
  • 选择器与左大括号之间保留一个空格
  • 冒号后保留一个空格

文件命名

  • 文件名全部使用小写字母
  • 多个单词之间使用连字符 - 分隔
  • HTML 文件使用 .html 扩展名
  • CSS 文件使用 .css 扩展名
  • JS 文件使用 .js 扩展名
  • 图片资源放在 images/ 目录下
  • 样式文件放在 css/ 目录下
  • 脚本文件放在 js/ 目录下

注释规范

  • 所有 HTML 文件必须包含文件用途的顶部注释
  • 复杂 CSS 规则必须添加注释说明用途
  • JS 函数必须添加 JSDoc 风格注释
  • 注释使用中文编写
  • 临时注释使用 // TODO: 标记
  • 废弃代码直接删除，不保留注释掉的代码

Git 提交规范

  • 提交信息使用中文编写
  • 格式：类型: 描述
  • 类型包括：feat（新功能）、fix（修复）、docs（文档）、style（样式）、refactor（重构）、chore（杂项）
  • 每次提交只包含一个逻辑变更
  • 提交前必须确保代码可运行

响应式设计

  • 使用移动优先（Mobile First）策略
  • 断点设置：768px（平板）、1024px（桌面）、1440px（大屏）
  • 优先使用相对单位 rem、em、%、vw、vh
  • 图片使用 max-width: 100% 确保自适应
  • 避免使用固定宽高

性能优化

  • CSS 文件控制在 500 行以内，超过则拆分
  • 避免使用过多 CSS 选择器嵌套（最多 3 层）
  • 动画优先使用 transform 和 opacity
  • 避免在动画中使用 width、height、top、left
  • 图片使用适当的格式（PNG、WebP、SVG）
  • 减少 HTTP 请求，合并静态资源

可访问性

  • 所有图片必须添加 alt 属性
  • 表单元素必须关联 label
  • 使用语义化 HTML 标签
  • 确保键盘可导航
  • 颜色对比度符合 WCAG 2.0 AA 标准
  • 为图标按钮添加 aria-label

浏览器兼容性

  • 支持 Chrome、Firefox、Safari、Edge 最近两个大版本
  • 使用 CSS 前缀确保兼容性：-webkit-、-moz-、-ms-
  • 使用 @supports 检测特性支持
  • 避免使用已废弃的 API
  • IE 浏览器不做兼容
